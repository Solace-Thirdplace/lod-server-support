## Implementation

The MC-independent core lives in `common/src/main/java/dev/vox/lss/common/dh`.
It implements DH Support protocol 15, official protocol 15, and official protocol
16 profiles; all ten control-message layouts; signed 28-bit positions; ordered
fragment assembly with request ownership; and format-1/2 terrain decoding.
Mismatched headers stop before payload interpretation.

Outer official strings use UTF-8 byte lengths. DH Support C2S uses byte lengths and S2C uses UTF-16 unit lengths;
the decoder counts validated scalars without consuming the next field. Mappings
use Java modified UTF-8. Material IDs/state properties are bounded data. Registry
lookup and unknown-block fallback are client work for P2.

Format 2 reconstructs the 62×62 interior and four edges, preserves the bottom-Y
predictor across columns within each blob, and requires repeated corners to match.
Raw, XZ (3), and one-shot Zstd (4) are supported; LZ4 (1) and Zstd stream (2) fail
as unsupported. Official XZ validates its stream end. DH Support reads exact
counts because its captured streams are unfinished. Its captured one-block
ceiling-AIR overrun is clipped only for the DH Support family.

Tiles distinguish unknown, partial, and complete vertical coverage. They preserve
identities, metadata, lights, flags, upstream hash and remote timestamps. DH Support timestamps are created/updated; official DTOs
are modified/created. Unknown
columns are never invented air. No-sky worlds normalize skylight to zero. A
versioned SHA-256 covers normalized content/world shape independently of timestamps
and compression.

One `DhMemoryBudget` covers retained messages, incomplete assembly, contiguous
join peaks, decoder working memory, mappings and retained tiles. Production
transport should use `decodeOwned`, consume messages in arrival order, and close
messages/results/tiles at ownership boundaries. The assembler belongs to one
session worker and is retired on replacement. Network registration, scheduling,
source settings, Voxy delivery and reset integration remain P2/P3 work.

Common's Shadow artifact owns XZ 1.10 and relocates it to
`dev.vox.lss.internal.xz`. No DH or SQLite dependency was added. The release checker
rejects stock XZ classes in flat/nested jars, codec references to stock XZ, missing
private runtime classes/notices, and duplicate/wrongly placed codec owners, for
all existing LSS/VSS artifact families.

## Validation

- 38 codec JUnit cases pass on Java 21: zero failures, errors or skips.
- All 119 common production Java sources compile on Java 21 without MC/loader deps.
- Six private parity combinations pass: two envelopes × three compression modes.
- A separate JVM replays both captures from an ASM-relocated common/XZ smoke jar
  with stock XZ absent; flat and Fabric-nested ownership checks pass. This is a
  packaging smoke, not Gradle's Shadow/platform output.
- Release-checker selftest: 124 cases pass, plus its nine SQLite helper tests.

Default enforced limits: 1 MiB/frame, 16 MiB compressed/tile, 64 MiB decoded/tile,
256 MiB owned work, 32 MiB XZ working memory, eight incomplete buffers, one million
encoded spans, 65,536 mappings, 4 MiB mapping text, 4,096 bytes/string and world
height at most 4,096. Buffers expire at ten seconds idle or sixty seconds total;
requests have a sixty-second lifetime. Tests check rejection and ownership release.
The largest captured tile accounts for 34,774,056 peak owned bytes in the packaged
decode: conservative budget accounting, not measured JVM RSS.
