# Xaero ownership baseline and extraction contract

Recorded before P5 extraction, 2026-09-09. Exact source identities and Java test imports/resources are in `test-baseline-sources.json`; execution cases are captured separately from Gradle XML. Historical pass counts do not accept this refactor.

All mutable state is created with the bridge/session. Tick and frame run on the same main client thread. Decode offers and disconnect retirement can run elsewhere. No new executor, cadence, limit or optional member descriptor is introduced by extraction.

| State | Permitted access and protection | Retirement and receipt owner |
| --- | --- | --- |
| `queue`, `queuedBytes`, `occupancy`, entry tile/origin/bytes | Decode offer, main drain and any-thread retirement under `queueLock`; occupancy is a volatile mirror; deferral count intentionally approximate across decode replacement | Acquisition OFF or world replacement clears; each replaced/removed entry closes its captured origin |
| `owed`, OwedRegion positions/busyTiles/origins, firstOwedMillis, `owedGauge`, `owedRegionsGauge` | Decode shedding and main probes/retirement under `owedLock`; volatile gauges reflect exact membership | Acquisition generation owns debt; evicted/cleared/released origins close exactly once |
| `acquisitionGeneration`, `retiringAcquisition`, Origin.closed/handle/release | Atomic generation/closed plus volatile retiring flag; publication/retirement under `acquisitionLock` | Origin captures the actual ingest receipt before work starts; never looks up a replacement manager; compare-and-set owns the one release |
| `deferredReports` | Main thread; collected under native ladder and drained after leaving its monitors | Captured origins travel with reports; OFF discards reports; disconnect settles them on main without forwarding into replacement |
| `awaitingRegions`, `regionsWaiting`, drain/owed rotation and idle counters | Main publishes immutable volatile region set/gauges, decode reads snapshot; rotation/idle counters main-only | Acquisition clear resets membership; absent classifier entry remains unknown and uses governed reporting |
| `pendingUpdates`, PendingUpdate lastTouch/stalledSince, `pendingUpdatesGauge` | Main only, keyed by dimension and coordinates, carries processor/world/tile identities; volatile gauge | OFF preserves committed native work. Disconnect/world replacement drops without a best-effort flush; no ingest receipts remain in committed rebuild work |
| `pumpCount`, frameFlushRan/frameActiveThisPump, framesSinceLastPump, rebuildSpentSinceLastPumpNanos | Main tick/frame shared interval | Tick consumes frame markers at its top, including early returns; disconnect main settlement resets interval |
| `written`, skippedNative, deferEvents, droppedOverflow/Stale/Expired, commitFailures, loadRequests, bufferUpdates, frameFlushes, rebuildNanos, droppedUpdates/Unloaded, skippedSettings, writtenCave, dropsReported, owedReported/Evicted | Atomic lifetime counters; no external objects retained | Lifetime counts survive disconnect; `rebuildNanosMax` is volatile and session-scoped |
| `dead`, consecutiveExtractFailures, sessionEndPending, settingsGateBroken, xaeroCrashed | Atomic/volatile decode/main/any-thread teardown; consecutiveFailures main-only | Disconnect clears thread-safe half immediately, then main settlement clears native objects and registration; no native calls from teardown thread |
| `registered`, consumer, lastWorldId | Main registration and native identity; consumer itself accepts decode work | Registration add-only mid-session; removal only at session end, preserving capability semantics |
| pumpDrainable, lastPumpMillis, undrainablePumps, blockedIdleSkips, haltSinceMillis, haltPeakOccupancy, haltWedged, wedgeSinceMillis, lastWedgeWarnMillis, settingsWritesOff | Main updates; externally read latches volatile; clocks and hysteresis main-only | Re-arm on disconnect in both any-thread and main halves to defeat late ladder finally writes |
| Test budget/clock seams | Configured before test operations; production constants unchanged | No runtime settings surface introduced |

Lock order stays acquisition → queue/debt for retirement. Decode never nests queue and debt or takes Xaero monitors. Main ladder takes native render pause before queue/debt as before; external/reentrant receipt probes must leave internal queue/debt/acquisition locks before invocation. Writes retain render/main/writer/region monitors and parent-before-leaf ordering. Native rebuild takes writer-pause then region and verifies identities/readiness before touching tile objects. No broad `close` joins acquisition and native-world lifetimes.

Budgets remain 64 commits/2 ms per pump, rebuild 2 ms plus existing borrow, default one rebuild per frame, shared frame/tick allowance, bounded probe floor, and bounded queue/debt/rebuild membership. Existing tests control values solely to test boundaries; extraction must preserve those seams.

Baseline behavior suite: `XaeroMapCompatTest`, `XaeroAcquisitionLifecycleTest`, `XaeroTileExtractorTest`, `XaeroWiringContractTest`, plus real-member/platform tests in their existing loader tasks. Retain old-origin extraction, overflow, reentrant deferred probe, commit cancellation, boundary shading, native save race, pending-rebuild OFF and same-dimension replacement controls. Required final live and performance matrix remains pending until actual final-artifact evidence is recorded.

## Extracted owners

`XaeroMapCompat` preserves loader-facing static entry points. `XaeroSession` owns registration, native-world identity, the gate ladder, failure containment and lifecycle coordination. `XaeroBindings` owns the immutable descriptor cache. `XaeroAcquisitionQueue` owns queue/debt membership, generation retirement, origin release and deferred reports. `XaeroRebuildScheduler` owns committed native updates and shared tick/frame allowance. `XaeroTileWriter` applies prepared pixels and neighbor slope invalidation under the existing native monitors. Component callbacks carry the originating receipt/generation; none looks up a replacement session.

The new `queuedGauge` is a volatile mirror written under queueLock alongside occupancy. `ModCompat.cachedXaeroStatus()` reads cached resolution, configured enablement, failure/retirement flags and queue/rebuild gauges; it performs no optional discovery, native probing, I/O or queue locking. Lifecycle-tagged UI snapshots remain the status service's responsibility. Every existing Xaero behavioral scenario now checks the queue gauge against membership under the lock in teardown.

`xaero-extraction-audit.json` is supplemental mechanical evidence: 81 of 82 original method bodies match after removing comments, whitespace, routing qualifiers, class renames and record-accessor syntax. The sole intentional difference adds the queue gauge mirror. This audit is not a substitute for descriptor, adverse callback/lifecycle tests or the required live/performance gates.

## Open-region window and heap belt (map ingestion, 2026-10-11)

Added by the map-ingestion program ([plan](../planning/2026-10-11-map-ingestion-journeymap-plan.md) §4, as built in §11). It fixes the unfocused-window OOM: Xaero releases map regions only on frames, so a starved client kept opening regions until the heap ran out. The thread topology, lock order and budgets above are unchanged.

| State | Permitted access and protection | Retirement |
| --- | --- | --- |
| `openRegionCap` | Set once at session init from the max heap (`heap / 96 MiB`, clamped 12 to 64; `-Dlss.xaero.openRegionWindow` overrides, 0 disables) | Session-scoped |
| `openRegions` (region key → 0 when committed, else the grant time), `openRegionsDimension`, `windowProgressMillis`, `openRegionsGauge` | Main thread only. Grants and commits admit a region (a grant always restamps its reservation, also onto a committed region); the probe walks the window oldest-first, keeps regions Xaero still has loading (1) or loaded (2) plus grants younger than `GRANT_RESERVE_MILLIS` (30 s), and drops the rest. Load grants are budgeted against the free slots, less loads still in flight outside the window; an expired reservation that never loaded is not turnover | Session-end main settlement clears the window and its dimension; the old world's regions are Xaero's to release |
| `windowBound`, `heapHolding` | Main thread; set by the pump ladder, cleared in its `finally` whenever the drain was not reached. `windowBound` means the window held work back this pump and turned over within the last 60 s (commits into regions it already holds do not clear it) | Session-end main settlement re-arms both |
| `memory` (`MapMemoryGuard`) | Production guard samples allow-listed old-generation pools after collections; halts above 0.85, releases below 0.70, with a 60 s halt / 10 s release duty cycle so a stuck heap cannot stop the map for good. Tests use `NEVER` or a scripted guard | Stateless toward the session |

While `windowBound` or `heapHolding`, the report to `IngestBackpressureGovernor` holds instead of wedging, so LOD downloads pause rather than the bridge giving up. Keep-visited stays on: an owed region never parks mid-rebuild. `/lss diag` and the `xaero` exporter group show `open_regions=N/cap` and `heap_fraction`. Tests: the window, grant-reservation, round-robin, pacing-flag and heap cases in `XaeroMapCompatTest`. Measured (L2, 26.2, 3 GB, one frame per 5 s): the window cut the post-stall peak from 12.8M to 8.1M map blocks (old-gen 0.75 to 0.51) at about 10 % slower fill; on that 256-region world neither arm ran out of memory.

## Cave layers, phase B-I (2026-10-13)

Added by the cave-layers work ([plan](../planning/2026-10-13-map-policy-and-xaero-cave-layers-plan.md) Part B, phase B-I). Every column writes the surface plus the layer Xaero shows; the thread topology, lock order and budgets above are unchanged.

| State | Permitted access and protection | Retirement |
| --- | --- | --- |
| `layerPlan` (dimension, current layer, depth, ignoreHeightmaps, worldSave) | Main thread publishes an immutable record into a volatile field at the top of every pump, before its gates and behind the crash shield; the decode thread reads it to choose each column's layers | Session-end main settlement clears it; a column whose dimension the plan does not name (or before Xaero's first read) writes the surface only — a guessed band ignored Xaero's roof probe, cave-mode switches and height clamp (review fold O3-2); in a ceiling dimension the column is still kept and fill-on-switch writes the shown layer from the store |
| Queue, bucket, waiting-region, grant, awaiting-region, owed, open-region and rebuild keys | Same protections as their tables above; every key now carries the Xaero layer (`TileKey`, `RegionKey`, `OwedKey`, `PendingKey`) because each layer has its own regions | Unchanged |
| `Receipt` (handle, generation, report latch) and per-tile `Origin` leases | One `Receipt` per delivered column, created in the decode callback; each reliable tile takes its own `deferAcceptance()` lease; the column reports at most once (compare-and-set on the receipt, which also covers the null-handle reporter path) | Each lease closes exactly once on commit, drop, debt release or retirement; an early return or throw in the offer releases every lease |
| `playerProbe`, `renderDistance`, `writingDistanceConfig` | Probes read the client on the calling thread (decode for the live cave bound and the capture gate, main for the native reach and the fill); the writing distance is read by the ladder's settings block, main only | Stateless toward the session |

The cave-layer wait gate is gone: a tile's layer and class are fixed at extraction, and a queued band tile commits to its own layer after Xaero switches bands. The natively-writable skip applies only to the layer Xaero writes, within its write distance (min(16, it) for a cave layer). That reach is the in-world one: with the map screen open Xaero's writer is uncapped, and while `caveStart` changes it writes only 4 chunks around the player, so the skip can briefly leave a tile to both writers (the latest commit wins, with the same pixels). A cave layer (band or Full) is written only within min(the server's LOD distance, 128) chunks of the player, as a Chebyshev square, in every dimension; the surface stays unbounded (`cave_out_of_range`). Without the bound an indoor Overworld player (Xaero's auto cave mode switches on under any roof) would double the map writes across the whole LOD radius. Queued tiles of a layer that is neither the surface nor the one Xaero shows expire silently after 600 held pumps (`dropped_stale_layer`): a region that never rests must not pin occupancy for map-only leftovers. Such a leftover still commits when its region takes it, but on every other path it never reports, owes or wins a load grant (review fold O3-1, one predicate `leftoverLayer`): an overflow eviction or the pre-gate shed closes it silently, a deferral expiry owes nothing, a held leftover bucket is no grant candidate (an in-flight load still counts against the budget), and a debt in a leftover layer is dropped before the owed probe's region lookup (which would create the region). A re-serve writes only the surface and the shown layer, so such a report or debt only re-downloaded the column and cost the position an ingest strike. Cave writes are off without the `cave-layers` bindings and in world-save mode. Overlay runs follow Xaero's `OverlayBuilder`: a new overlay only when the block changes (Xaero compares particle textures, and every water `LEVEL` shares one, so a run keeps its first state), and past the 10-overlay cap the last overlay keeps taking opacity, on the surface and in cave layers alike. The parity oracle gives the real writer a stub `MapProcessor`, so overlay `glowing` is compared too, and the binding-surface test checks that the NeoForge and floor builds run the same `loadPixel`/`loadPixelHelp`/`writeChunk`/`getSectionBasedHeight` instructions as the Fabric build the oracle runs. `/lss diag` and the `xaero` exporter group add `written_cave`, `layer` and `mode`; `cave_layer_waits` is removed. Tests: `XaeroCaveLayersTest`, `XaeroLoadPixelParityTest`, `XaeroBindingSurfaceTest`.

## Cave layers: fill-on-switch (2026-10-13)

Phase B-II (best-effort writes into the bands Xaero does not show) was replaced after three spike runs. It doubled reliable load latency, used 1.8x the heap and lost 30% of its tiles. On a pre-generated world it wrote 7 tiles: the whole Nether radius arrives in about 100 s, while LSS delivers each column only once. Writing the layer Xaero shows works well: its regions rest and save at the normal cadence. So the bridge now keeps the columns and writes a band when Xaero switches to it.

In a ceiling dimension (`DimensionType.hasCeiling`: the Nether and modded equivalents), every delivered column is captured into a disk store. Live arrivals still write the surface plus the layer Xaero shows, exactly as in phase B-I. When Xaero's layer (a Layered band, or Full) changes and stays put for the debounce, a fill job reads the stored columns within min(the server's LOD distance, the radius cap) of the player: a Chebyshev square, the shape LSS serves, nearest (Euclidean) first. It skips positions already written to that layer this session, re-extracts the layer's tile and offers it to the reliable queue for the current layer. A player who moves more than a quarter of the radius from the job's centre gets a new pass (coverage skips what the last one wrote). Once per switch, a pass that left positions unwritten re-arms 30 s after it finished. The Overworld and the End keep phase B-I behaviour (apart from the cave-layer bound above).

| State | Permitted access and protection | Retirement |
| --- | --- | --- |
| `XaeroColumnStore` (segments, index, active key, read-handle LRU, held forgets) | One daemon IO thread owns every file, handle and the index; captures queue with a count and byte bound and drop past it (each bound rolls back only what it added); forgets queue with their own bound and are held across a clear; reads and the nearest-first position list are IO-thread tasks; read handles open lazily, at most 8 per store plus the segment being written | Closes at session end and around every column-cache clear (`BucketTenant`); files survive sessions |
| `XaeroLoadStats` followed grants (at most 512 Xaero `MapRegion` references) | Main thread only (every observation site runs in the ladder) | Cleared at session end, on a Xaero world-id change and on a dimension change (review fold O3 N3); a grant is forgotten after 5 minutes |
| `xaeroWorldId`, held captures | The pump publishes Xaero's world id (`getCurrentWorldId`) with the plan into a volatile field; the decode thread keys captures by it. Captures made before it is known are held (512 columns / 16 MiB, under their own monitor) and keyed in order once it is | The id clears at session end; held captures drop at session end (their positions read stale for the session) |
| `XaeroBandFill` trigger state and current job | Main thread (the pump) decides; the job's progress fields are volatile; one daemon worker decodes, extracts and offers; the worker's give-up clears the current job only by compare-and-set (review fold O4-F9); the last job (diag only) and the fill level hold no `ClientLevel` (O4-F1) | Cancelled by the next layer switch, a dimension, world or bucket change, Xaero's world id changing, session end, acquisition off (`lod.receive`), the server's deny, local ingestion off, both of Xaero's own map-writing switches off, world-save mode or missing cave bindings |
| Coverage (positions written to a layer this session) | Per (dimension, layer) set, each guarded by its own monitor; the drain marks commits and native-writer skips of cave tiles, a live capture invalidates every layer of its position, the worker reads | Cleared at session end and when Xaero's world id changes (session-scoped, so a new session or a Xaero map reset heals by refilling); kept across Receive OFF |
| Fill entries in the reliable queue | Under `queueLock`, counted apart (`fillCount`/`fillBytes`): excluded from `occupancy`, so the LSS backpressure report never slows Voxy for map-only work; offered only into room and never over a queued key; a live tile of the same key takes the entry's place, and a live overflow evicts fill entries first. Each carries its job's receipt as its generation token: cancelling the job revokes it, so `queueLock` refuses an offer racing the cancel and the drain drops the job's queued entries (review fold O3 N2) | Same retirement as the queue; lease-free origins (`Origin.live == false`) never report, owe or re-serve |

**Store.** The store is keyed like the client column cache, then by Xaero's world: its files sit flat inside the cache's bucket directory as `<dimension>.w<hash of Xaero's world id>.xfill.<n>`. So address aliases and `.world-<hex>` sub-buckets apply, every bucket clear deletes it (`/lss clearcache`, `/lss reset` and the reset sweep), and two Xaero worlds that share one LSS bucket (a proxy backend switch without a disconnect, two backends with one seed, or `cache.split_by_world: false`) never fill one's terrain into the other's map, in that session or a later one (review fold O4-F5); a Xaero world change forgets the session's coverage and job, and the old world's store stays for a return. Segments are append-only. A segment starts with a header carrying a registry fingerprint: the store and codec format versions, the world data version, every block's key and state count in id order, the biome id-to-key order and the dimension's heights. Records are CRC32-framed. A torn tail stops the scan, and a CRC failure drops that record; a record that passes its CRC but will not decode or extract is dropped (`store_corrupt`, `fill_bad_columns`) and the job goes on. Every such drop, and every dropped capture, writes a tombstone (codec 2, no payload) that a reopen honours, so a later session neither fills the old copy into another band nor re-counts a bad record (review fold O4-F3). Only a write discards a store written under another fingerprint or format version; a read finds nothing and never deletes a file, also one with an unusable header (the first write into that store deletes it; O4-F8). A session's first write appends to the newest segment when its tail is clean and it has room, a torn tail starts a new one, and a new segment takes the number after every file seen and is created exclusively (O4-F4). The latest record of a position wins, so a re-serve overwrites. The payload is the client decode format (`ColumnSections.decode`) of the sections inside the level's height, zstd-compressed when the native is present and raw otherwise.

One total cap applies to every store: `integrations.map_ingestion.nether_store_mib` (client settings, 256 MiB by default, 16 MiB minimum, 1024 MiB maximum; 0 = no store, its files deleted, and no fill on switch), applied every pump, so `/lss reload` changes it; a lowered cap trims at the store's next open or write, usually the next Nether visit. The maximum bounds the heap: the active store's index costs ~100 bytes per stored column, ~2.5% of its disk bytes, ~25 MiB at 1024 MiB (review fold O4-F6; a file with more applies the maximum with a normalization note). The key lives in the experimental sidecar so the main client file stays readable by 0.18.0. `-Dlss.xaero.bandFill.storeMB` overrides it for development. Eviction is least-recently-used at segment granularity: other stores go whole first, then the active store's oldest segment, and a record a fill reads from the older half of the segments is copied forward once the store is past three quarters of the cap. Progress is counted in bytes actually freed: a store whose files will not delete is skipped for the pass, and a pass is bounded. The active bucket is recognised by its directory's file key (a case-insensitive filesystem or a link never makes it "another store"). A segment whose header write fails is closed and deleted; after 8 failed writes in a row the store stops capturing for the session with one warning.

Nothing is captured while the server denies map ingestion, local map ingestion or acquisition is off, Xaero is in world-save mode, the cave bindings are missing, or the player is in another dimension; in singleplayer nothing is captured until the layer plan for that dimension is read (it may be world-save mode). Captures go on while Xaero's own "Load New Chunks"/"Update Chunks" switches are off (review fold F1-NIT2, decided): those stop map writes, not LSS's terrain copy, and nothing re-sends the columns, so the copy is what writes the shown band once writing returns. A capture the store drops leaves its position "stale" for the session (fills skip it until a later capture of that position is stored) and forgets the older copy for good with a tombstone.

**Pacing.** The worker offers only while the reliable queue holds fewer than `queueHigh` entries and the heap belt is not holding. Live arrivals therefore keep priority, and fill tiles go through the same window, grants and rebuild budget as live tiles of the current layer.

**Containment.** The pump's store-setting and fill-trigger steps run inside the ladder's containment: a failure is a bridge failure (`noteFailure`, the death latch), and an Error other than an assertion is rethrown (review fold F1-NIT3).

Tunables (client JVM system properties; defaults in parentheses): `lss.xaero.bandFill` (true; false is the B-I arm, which detaches the store without deleting it), `lss.xaero.bandFill.storeMB` (unset: the client setting), `.debounceMillis` (1500), `.radiusChunks` (128), `.queueHigh` (128), `.batch` (64).

`/lss diag` shows what a player or admin needs: `band_fill=on|off`, the store size (and "capture off" after write failures) and the last fill's layer with its covered/target count and state. The `xaero` exporter group carries everything: the store gauges (`store_columns`, `store_bytes`, `store_evictions`, `store_capture_drops`, `store_captured`, `store_corrupt`), the fill counters (jobs started, completed, cancelled and failed, tiles offered and committed, skips for coverage and for queued keys, `fill_bad_columns`, `fill_moved_passes`, `fill_rearms`, `fill_queued`), the last job's `fill_layer`, `fill_target` (stored positions in its square), `fill_covered`, `fill_age_ms`, `fill_queue` and `fill_last_ms`, and the reliable-path instrumentation: region-load latency (`load_ms_p50`/`p95` as histogram bucket bounds; -1 means no samples, -2 means past 25.6 s), `region_vanished`, defer reasons, `capped_pumps`, `pending_updates`, `buffer_updates`, `dropped_updates`, `to_save`/`to_save_max` (Xaero's save queue), `cave_out_of_range` and `dropped_stale_layer`. The `xaero-nether-bands` soak scenario records the spike, and `check_soak.py` judges the fill law. The A/B ratios against the fill-off arm are read by hand. Tests: `XaeroColumnStoreTest`, `XaeroBandFillTest`, `XaeroCaveLayersTest`, `MapIngestionSettingsTest`.
