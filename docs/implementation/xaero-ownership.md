# Xaero ownership baseline and extraction contract

Recorded before P5 extraction, 2026-09-09. Exact source identities and Java test imports/resources are in `test-baseline-sources.json`; execution cases are captured separately from Gradle XML. Historical pass counts do not accept this refactor.

All mutable state is created with the bridge/session. Tick and frame run on the same main client thread. Decode offers and disconnect retirement can run elsewhere. No new executor, cadence, limit or optional member descriptor is introduced by extraction.

| State | Permitted access and protection | Retirement and receipt owner |
| --- | --- | --- |
| `queue`, `queuedBytes`, `occupancy`, entry tile/origin/bytes | Decode offer, main drain and any-thread retirement under `queueLock`; occupancy is a volatile mirror; deferral count intentionally approximate across decode replacement | Acquisition OFF or world replacement clears; each replaced/removed entry closes its captured origin |
| `owed`, OwedRegion positions/busyTiles/origins, firstOwedMillis, `owedGauge`, `owedRegionsGauge` | Decode shedding and main probes/retirement under `owedLock`; volatile gauges reflect exact membership | Acquisition generation owns debt; evicted/cleared/released origins close exactly once |
| `acquisitionGeneration`, `retiringAcquisition`, Origin.closed/handle/release | Atomic generation/closed plus volatile retiring flag; publication/retirement under `acquisitionLock` | Origin captures the actual ingest receipt before work starts; never looks up a replacement manager; compare-and-set owns the one release |
| `deferredReports` | Main thread; collected under native ladder and drained after leaving its monitors | Captured origins travel with reports; OFF discards reports; disconnect settles them on main without forwarding into replacement |
| `awaitingRegions`, `regionsWaiting`, drain/owed rotation and idle counters | Main publishes immutable volatile region set/gauges, decode reads snapshot; rotation/idle counters main-only | Acquisition clear resets membership; absent classifier entry remains unknown and uses governed reporting |
| `pendingUpdates`, PendingUpdate lastTouch/stalledSince, `pendingUpdatesGauge` | Main only, keyed by dimension and coordinates, carries processor/world/tile identities; volatile gauge | OFF preserves committed native work. Disconnect/world replacement drops without a best-effort flush; no ingest receipts remain in committed rebuild work |
| `pumpCount`, frameFlushRan/frameActiveThisPump, framesSinceLastPump, rebuildSpentSinceLastPumpNanos | Main tick/frame shared interval | Tick consumes frame markers at its top, including early returns; disconnect main settlement resets interval |
| `written`, skippedNative, deferEvents, droppedOverflow/Stale/Expired, commitFailures, loadRequests, bufferUpdates, frameFlushes, rebuildNanos, droppedUpdates/Unloaded, skippedSettings, writtenCave, bestEffortWritten/Dropped, dropsReported, owedReported/Evicted | Atomic lifetime counters; no external objects retained | Lifetime counts survive disconnect; `rebuildNanosMax` is volatile and session-scoped |
| `dead`, consecutiveExtractFailures, sessionEndPending, settingsGateBroken, xaeroCrashed | Atomic/volatile decode/main/any-thread teardown; consecutiveFailures main-only | Disconnect clears thread-safe half immediately, then main settlement clears native objects and registration; no native calls from teardown thread |
| `registered`, consumer, lastWorldId | Main registration and native identity; consumer itself accepts decode work | Registration add-only mid-session; removal only at session end, preserving capability semantics |
| pumpDrainable, lastPumpMillis, undrainablePumps, blockedIdleSkips, haltSinceMillis, haltPeakOccupancy, haltWedged, wedgeSinceMillis, lastWedgeWarnMillis, settingsWritesOff | Main updates; externally read latches volatile; clocks and hysteresis main-only | Re-arm on disconnect in both any-thread and main halves to defeat late ladder finally writes |
| Test budget/clock seams | Configured before test operations; production constants unchanged | No runtime settings surface introduced |

Lock order stays acquisition → queue/debt for retirement. Decode never nests queue and debt or takes Xaero monitors. Main ladder takes native render pause before queue/debt as before; external/reentrant receipt probes must leave internal queue/debt/acquisition locks before invocation. Writes retain render/main/writer/region monitors and parent-before-leaf ordering. Native rebuild takes writer-pause then region and verifies identities/readiness before touching tile objects. No broad `close` joins acquisition and native-world lifetimes.

Budgets remain 64 commits/2 ms per pump, rebuild 2 ms plus existing borrow, default one rebuild per frame, shared frame/tick allowance, bounded probe floor, and bounded queue/debt/rebuild membership. Existing tests control values solely to test boundaries; extraction must preserve those seams.

Baseline behavior suite: `XaeroMapCompatTest`, `XaeroAcquisitionLifecycleTest`, `XaeroTileExtractorTest`, `XaeroWiringContractTest`, plus real-member/platform tests in their existing loader tasks. Retain old-origin extraction, overflow, reentrant deferred probe, commit cancellation, boundary shading, native save race, pending-rebuild OFF and same-dimension replacement controls. Required final live and performance matrix remains pending until actual final-artifact evidence is recorded.

## Extracted owners

`XaeroMapCompat` preserves loader-facing static entry points. `XaeroSession` owns registration, native-world identity, the gate ladder, failure containment and lifecycle coordination. `XaeroBindings` owns the immutable descriptor cache. `XaeroAcquisitionQueue` owns queue/debt membership, generation retirement, origin release and deferred reports. `XaeroRebuildScheduler` owns committed native updates and shared tick/frame allowance. `XaeroTileWriter` applies prepared pixels and neighbor slope invalidation under the existing native monitors. Component callbacks carry the originating receipt/generation; none looks up a replacement session.

The new `queuedGauge` is a volatile mirror written under queueLock alongside occupancy. `ModCompat.cachedXaeroStatus()` reads cached resolution, configured enablement, failure/retirement flags and queue/rebuild gauges; it performs no optional discovery, native probing, I/O or queue locking. Lifecycle-tagged UI snapshots remain the status service's responsibility. Every existing Xaero behavioral scenario now checks the queue gauge against membership under the lock in teardown.

`xaero-extraction-audit.json` is supplemental mechanical evidence: 81 of 82 original method bodies match after removing comments, whitespace, routing qualifiers, class renames and record-accessor syntax. The sole intentional difference adds the queue gauge mirror. This audit is not a substitute for descriptor, adverse callback/lifecycle tests or the required live/performance gates.

## Open-region window and heap belt (map ingestion, 2026-10-11)

Added by the map-ingestion program ([plan](../planning/2026-10-11-map-ingestion-journeymap-plan.md) §4, as built in §11). It fixes the unfocused-window OOM: Xaero releases map regions only on frames, so a starved client kept opening regions until the heap ran out. The thread topology, lock order and budgets above are unchanged.

| State | Permitted access and protection | Retirement |
| --- | --- | --- |
| `openRegionCap` | Set once at session init from the max heap (`heap / 96 MiB`, clamped 12 to 64; `-Dlss.xaero.openRegionWindow` overrides, 0 disables) | Session-scoped |
| `openRegions` (region key → 0 when committed, else the grant time), `openRegionsDimension`, `windowProgressMillis`, `openRegionsGauge` | Main thread only. Grants and commits admit a region (a grant always restamps its reservation, also onto a committed region); the probe walks the window oldest-first, keeps regions Xaero still has loading (1) or loaded (2) plus grants younger than `GRANT_RESERVE_MILLIS` (30 s), and drops the rest. Load grants are budgeted against the free slots, less loads still in flight outside the window; an expired reservation that never loaded is not turnover | Session-end main settlement clears the window and its dimension; the old world's regions are Xaero's to release |
| `windowBound`, `heapHolding` | Main thread; set by the pump ladder, cleared in its `finally` whenever the drain was not reached. `windowBound` means the window held work back this pump and turned over within the last 60 s (commits into regions it already holds do not clear it) | Session-end main settlement re-arms both |
| `memory` (`MapMemoryGuard`) | Production guard samples allow-listed old-generation pools after collections; halts above 0.85, releases below 0.70, with a 60 s halt / 10 s release duty cycle so a stuck heap cannot stop the map for good. Tests use `NEVER` or a scripted guard | Stateless toward the session |

While `windowBound` or `heapHolding`, the report to `IngestBackpressureGovernor` holds instead of wedging, so LOD downloads pause rather than the bridge giving up. Keep-visited stays on: an owed region never parks mid-rebuild. `/lss diag` and the `xaero` exporter group show `open_regions=N/cap` and `heap_fraction`. Tests: the window, grant-reservation, round-robin, pacing-flag and heap cases in `XaeroMapCompatTest`. Measured (L2, 26.2, 3 GB, one frame per 5 s): the window cut the post-stall peak from 12.8M to 8.1M map blocks (old-gen 0.75 to 0.51) at about 10 % slower fill; on that 256-region world neither arm ran out of memory.

## Cave layers, phase B-I (2026-10-13)

Added by the cave-layers work ([plan](../planning/2026-10-13-map-policy-and-xaero-cave-layers-plan.md) Part B, phase B-I). Every column writes the surface plus the layer Xaero shows; the thread topology, lock order and budgets above are unchanged.

| State | Permitted access and protection | Retirement |
| --- | --- | --- |
| `layerPlan` (dimension, current layer, depth, ignoreHeightmaps, worldSave) | Main thread publishes an immutable record into a volatile field at the top of every pump, before its gates and behind the crash shield; the decode thread reads it to choose each column's layers | Session-end main settlement clears it; a column whose dimension does not match uses Xaero's defaults (Layered, (playerY+4)>>4) in a ceiling dimension and the surface elsewhere |
| Queue, bucket, waiting-region, grant, awaiting-region, owed, open-region and rebuild keys | Same protections as their tables above; every key now carries the Xaero layer (`TileKey`, `RegionKey`, `OwedKey`, `PendingKey`) because each layer has its own regions | Unchanged |
| `Receipt` (handle, generation, report latch) and per-tile `Origin` leases | One `Receipt` per delivered column, created in the decode callback; each reliable tile takes its own `deferAcceptance()` lease; the column reports at most once (compare-and-set on the receipt, which also covers the null-handle reporter path) | Each lease closes exactly once on commit, drop, debt release or retirement; an early return or throw in the offer releases every lease |
| `playerProbe`, `renderDistance`, `writingDistanceConfig` | Probes read the client on the calling thread (decode for the mismatch band, main for the native reach); the writing distance is read by the ladder's settings block, main only | Stateless toward the session |

The cave-layer wait gate is gone: a tile's layer and class are fixed at extraction, and a queued band tile commits to its own layer after Xaero switches bands. The natively-writable skip applies only to the layer Xaero writes, within its write distance (min(16, it) for a cave layer). Cave writes are off without the `cave-layers` bindings and in world-save mode. `/lss diag` and the `xaero` exporter group add `written_cave`, `layer`, `mode` and `best_effort_written`/`best_effort_dropped` (0 until phase B-II); `cave_layer_waits` is removed. Tests: `XaeroCaveLayersTest`, `XaeroLoadPixelParityTest`, `XaeroBindingSurfaceTest`.

## Cave layers, phase B-II: best-effort bands (2026-10-13)

Added by phase B-II of the [plan](../planning/2026-10-13-map-policy-and-xaero-cave-layers-plan.md) (§B6), for the §B0 spike. In a ceiling dimension in Layered mode, every band Xaero does not show is extracted for columns within min(`radiusChunks`, the server's LOD distance) chunks of the player, and written on a separate best-effort path that never touches the reliable path's occupancy, backpressure report, owed set, pacing hold or leases. All-void band tiles are not enqueued. With the switch off, or without the `best-effort` bindings, behavior is phase B-I.

| State | Permitted access and protection | Retirement |
| --- | --- | --- |
| `XaeroBestEffortPipeline.queue` ((layer, chunk) to entry, insertion-ordered, latest tile wins) and `queuedBytes` | Under the pipeline's own `lock` (decode offers, main drain, any-thread clears); never held while taking the session's queue lock or a Xaero monitor. Count and byte caps: a column whose bands do not fit is refused before extraction (`refused`); expiry and stale entries drop, and drop-oldest overflow remains as the belt for concurrent offers. Entries hold lease-free origins, so a drop never reports or owes anything | Cleared (counted as `cleared`, not as drops) by every queue clear the reliable path does: toggle, acquisition end, session end |
| Best-effort window (`open`: region to slot) and grant history | Main thread, in the pump ladder. Own share of open regions; never sets `windowBound`. A slot with queued tiles is kept visited (Xaero parks an unvisited, unwritten region after 1 s). A slot leaves when Xaero parks or removes the region, when a grant's request is lost or queued past 120 s, after `idleReleaseMillis` with nothing queued, or after `maxHoldMillis` when no batch is mid-commit (Xaero's `MapLimiter` governs its residency from there) | `resetSession()` in session-end settlement |
| `XaeroRebuildScheduler.bestEffortUpdates` (best-effort owed rebuilds) | Main thread. Its own map and cap (`maxRebuildDebt`), separate from the reliable `pendingUpdates`, so best-effort debt never counts against the reliable hard cap. A reliable commit into a tile chunk promotes its entry; a best-effort commit into a reliable one only touches it. Its regions are kept visited like the reliable ones (the park guard). Flushed after the reliable pass, only when no reliable rebuild is due, within the base budget and the caller's rebuild cap (never the borrow) | Cleared with the reliable map at session end and on a dead bridge |
| `XaeroLoadStats` (followed grants, latency histograms, vanished counters) | Main thread only. At most 512 followed grants, each followed at most 5 minutes | Followed grants cleared at session end; histograms and counters are cumulative |

The drain runs after the reliable drain, on the pump budget the reliable drain left, under its own commit cap and its own rebuild-debt cap. The reliable path goes first: while the last reliable drain retained anything (deferred, awaiting a load, window-held, capped or cut by its budget), a reliable region waits on a load, or the reliable rebuild debt is past its soft cap, best-effort neither commits nor grants. The one exception is a just-loaded granted region, whose batch starts committing in the same pump that first sees it at loadState 2, bounded by the commit cap and one pump budget, with at least one commit (its first may use a small headroom past the debt cap). That beats the 600 ms save of a layer nobody renders and the `countChunks()==0` removal after an empty first save. Loaded regions get batches too, never a trickle: each commit burst into a non-rendered layer costs Xaero a 600 ms save and a recache, so a bucket commits only once ready (at least K tiles, or its oldest T old), and a started batch drains without re-waiting. A load is granted only when the reliable path is clear, Xaero's `getToSave()` is empty and fewer than `maxLoads` best-effort loads are outstanding; it is requested without priority, behind every front-inserted request, and a request Xaero refuses mid-drain is retried. Each grant is for one ready (layer, region) batch, largest first.

Spike round 1 (2026-10-13) showed why: with the round-1 design the reliable SURFACE layer, itself a non-current layer in the Nether, held 1,000 to 1,900 tiles for about nine minutes while the shown band kept pace. Its regions sat on Xaero's save and recache cycle and its load queue, shared with the best-effort regions.

Tunables (system properties on the client JVM; defaults in parentheses): `lss.xaero.bestEffortBands` (true), `lss.xaero.bestEffort.batchTiles` K (64), `.batchMillis` T (8000), `.radiusChunks` (128), `.maxQueue` (4096), `.maxQueueMB` (24), `.ttlMillis` (60000), `.window` (-1: a quarter of the open-region window, 2 to 16, or 8 with the window off), `.commitsPerPump` (32), `.maxLoads` (2), `.idleReleaseMillis` (10000), `.maxHoldMillis` (30000), `.maxRebuildDebt` (64).

`/lss diag` and the `xaero` exporter group add the best-effort counters: enqueued, written, dropped and drops by reason (overflow, expired, stale, other), cleared, void, skipped-native, queued, open over the share, batches, grants, re-grants and the most grants any one (layer, region) took. They also add reliable and best-effort region-load latency from grant to loadState 2 (p50/p95 as histogram bucket bounds: -1 means no samples, -2 means past 25.6 s), regions that vanished after a grant before their first commit, and Xaero's save and load queue sizes (`to_save`, `to_load` and their maxima). Round 2 adds the coupling diag: per class, owed rebuilds (`pending_updates`, `best_effort_pending_updates` over its cap), rebuilds done, dropped and stalled, and why commits were deferred (`not_resting`, `paused`, `capacity`, `tile_busy`, `other`). It also adds reliable drains stopped by the hard cap (`capped_pumps`), what the last reliable drain retained split surface/cave with its region count (`held=`), pumps best-effort held for the reliable path, refused band tiles, and load metrics that separate a load/remove loop from trickling arrival: grants released without a commit (`best_effort_fruitless_grants`), grants per 1000 tiles written, the highest per-minute re-grant rate of any region, and refused non-priority requests. The `xaero-nether-bands` soak scenario records the spike; `check_soak.py` judges the single-run criteria, and the A/B ratios against the B-I arm are read by hand. Tests: `XaeroBestEffortTest` (including a best-effort debt flood that never defers a reliable commit, reliable rebuilds first, the reliable-backlog hold, batching for loaded regions, and non-priority grants), plus the routing cases in `XaeroCaveLayersTest`.
