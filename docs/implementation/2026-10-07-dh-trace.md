# DH event tracing

Date: 2026-10-07 (local). Applies to experimental MC1.21.1 DH compatibility on
Fabric and NeoForge.

## Empty-trace cause

The user's `lss-trace-20261007-204806.jsonl` is zero bytes. The client log confirms
that tracing started at 20:48:06 and stopped at 20:48:44 without an IO error.
All existing trace producers were in the native LSS request/decode pipeline;
the DH adapter never emitted events. Native acquisition is suppressed when DH
is selected, so the successfully opened writer had no rows to write.

The later diagnostics establish continued acquisition, not a complete stall:
between 20:49:44 and 20:50:07, accepted tiles rose from 299 to 325 and enqueued
columns from 4013 to 4347. Decode queue depth reached six, and pressure drops rose
from 355 to 423 while Voxy backlog stayed zero. The old combined pressure count
cannot establish whether raw frame loss or live-update deferral caused the visible
pause. This change fixes tracing, not the still-unconfirmed cause of that pause.

## Changed behavior

`/lss trace` now immediately writes and flushes a `trace_start` row, even when no
terrain events arrive. The shared DH client owner emits `dh_status` at most once
per second, including while waiting for configuration or world initialization.
A new trace restarts that cadence immediately.

`dh_request` records a request when sent, with its correlation ID, tile, generation
flag and timestamp. Owned `dh_reply` records the same ID/tile, payload presence
and request age. `dh_refusal` and `dh_timeout` record refusal codes and expired
request IDs. `dh_pressure` separates inbound queue overflow, owned-byte pressure,
assembly/decode resource limits, live-update backlog/resource deferral and recovery
queue pressure. Status rows include raw loss counts separately from the combined
pressure count, pending request ages, player chunk coordinates and queue depths.
Reply and pressure hooks also run on the decoder/transport threads; the existing
synchronized writer remains necessary.

Tracing remains opt-in and local, with the existing 64 MiB ceiling and buffered
event writes. Records contain coordinates but no server address, logical world
key, raw terrain payload or server-supplied reason text. Diagnostic exports retain
their separate privacy contract. Native trace event hooks remain in place.

The redundant `/lss dhstatus` alias is removed on both loaders. `/lss diag` shows
the active source's diagnostics; `/lss status` and `/lss diagnostics export` remain
available. Current manual instructions use `/lss diag`.

The shorter “Use DH” tooltip is included in English and both Chinese locales.
The [accepted queued-write limitation](2026-10-07-dh-accepted-limitations.md) remains
unchanged.
