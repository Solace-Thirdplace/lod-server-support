# Installation and first connection

Choose the exact Minecraft line and loader in the [compatibility catalog](../compatibility.md). Its build, shipping, renderer and optional-integration facts are separate: a shipped jar does not establish that an arbitrary Voxy, Xaero, Sodium or Connector combination works. Match optional components to the line's reviewed profiles under `config/compatibility/profiles/`; installed or blocked profiles are not live certification. Minecraft 1.21.x uses Java 21; 26.x uses Java 25. The 26.1 support line targets Minecraft 26.1.2.

Install the matching LSS Fabric/NeoForge mod in the server's `mods` directory, or the Paper plugin in `plugins`. Install the matching client mod for every participating client, with a compatible LOD consumer. Voxy terrain and map ingestion (Xaero's World Map 1.42.0+ or JourneyMap 6.0.0+) are distinct consumer paths. Map ingestion writes persistent map data and is on in new client settings files (`integrations.map_ingestion.enabled`); an upgraded file keeps the choice written in it (generated LSS 0.16/0.17 files say off), while a hand-trimmed file without the key follows the new default. Consult the catalog before selecting NeoForge or Folia; Folia remains experimental, and absent platform rows cannot be supplied by another line's jar.

Start once to generate configuration. Fabric/NeoForge use `config/lss-server-config.yaml` and the client uses `config/lss-client-config.yaml`. Paper uses its plugin data directory, normally `plugins/LodServerSupport/lss-server-config.yaml`. VSS prefers the corresponding `vss-` filenames and its branded data directory; an existing adopted LSS/VSS file remains the active save target. Read the actual startup log and file instead of creating a second copy. Keep a backup before changing an established installation. Upgrading the Minecraft version (for example 26.2 to 26.3) rebuilds the LOD store from scratch on the first start, because stored columns are tied to the game version, and the backfill walks the world again; expect extra CPU and disk activity for a while, and clients re-download terrain the upgraded server re-saves.

Join the server, run `/lss status`, then `/lss diag`. Look for negotiated service, reception ON and an available consumer. Operators can use `/lsslod help`, `/lsslod diag` and `/lsslod store status`. VSS command roots are `/vss` and `/vsslod`. A successful connection does not prove far-player rendering or map writes; check those features separately. See [troubleshooting](troubleshooting.md), [settings](../reference/settings.md), and [status and settings](status-and-presets.md) for the next step.

Startup migrates legacy JSON when no YAML exists, preserving the original and an exact-byte backup. A malformed authoritative file does not fall back to defaults or another format. Edit YAML and run `/lsslod reload` (server) or `/lss reload` (client); Sodium Apply saves and reloads client settings automatically. Pending restart/reconnect values remain inactive until that boundary. See the [settings reference](../reference/settings.md).
