# LSS 0.18.0 release preparation

Prepared 2026-10-12. **All six pinned release candidates pass the exact-version local gate and the hosted checks.** Identities, counts and jar hashes are in the [manifest](../implementation/2026-10-12-v0.18.0-release-preparation.json). The release branches are pushed to PRs #343–#348. Nothing has been merged, tagged or published.

0.18.0 is the first release on Minecraft 26.3, which is now `main`. 26.2 continues on `support/mc26.2` and now takes a `+mc26.2` tag suffix.

## What 0.18.0 contains

- **Minecraft 26.3.** This is a new line for Fabric, Paper/Purpur and NeoForge, with no Folia because there is no 26.3 build. Voxy has not published a 26.3 build, so a 26.3 client gets map ingestion and far players but no LOD terrain until it does.
- **JourneyMap map ingestion.** It comes with the neutral `integrations.map_ingestion` setting, which is on in new settings files. JourneyMap's 1.21.10 beta is unsupported.
- **LOD distance 0** switches LOD service off in that dimension or world.
- **Post-0.17 review fixes.** The one MAJOR is the `<dim>.maponly` cache marker: a map-only download no longer seals terrain against a later Voxy install.

## Manual and compatibility validation

**Manual run.** Astra ran the release manual tests on 2026-10-12 against the review heads, on real GPU clients for all six lines. Results are in `~/projects/lss-fix/astra-results/2026-10-12/RESULTS.md`, outside the repo: 24 pass, 1 blocked (the 2 GiB B6 fill was stable but did not finish in 15 minutes) and 1 optional skip. The two failures it reported are resolved:

- **A1 (C2ME crash on the 26.3 test server).** This was the test rig, not LSS. `test-server.sh` hand-pinned Fabric Loader 0.19.3, whose MixinExtras 0.5.4 fails on C2ME 0.4.2-alpha.0.90+26.3. The script now derives the loader version from `gradle.properties`. Downloads now carry a source-URL stamp so pin bumps reach cached rigs. This is ported to every line, and C2ME is bumped to each line's latest build. The server now boots on every line with its latest C2ME, and the save hook marks a setblock dirty under it.
- **A3 (no armor trims on 26.3 far players).** This was a wrong test expectation, not a regression. Far players cross the wire as bare item ids, so trims, dye and glint are not shown on any line. The manual-test guide is corrected.

The 1.21.1 Xaero map corner cells are the known accepted 1.21.1 client render-edge seam at the rig's view distance of 4.

## Hosted checks (2026-10-12)

The six release branches were pushed together and PRs #343–#348 were opened without merging. Catalog, settings, build and client-gametest checks passed on all six (1.21.1 has no client-gametest job). The first attempt on 26.1, 1.21.11 and 1.21.10 failed at about 09:03 UTC. In that window `repo.papermc.io` failed to serve the Paper dev bundle, so `paperweightUserdevSetup` could not resolve it. Minutes later the repository answered HTTP 200 again, and the failed jobs passed on one re-run.

## Known limits

- Voxy has not published a 26.3 build.
- Folia has no 26.3 build. Folia remains experimental, and is unavailable on 1.21.1 and 1.21.10.
- NeoForge remains best-effort. Its distant-player rendering exists only on 1.21.1.
- Far players show base armor and items only: no trims, dye or glint.
- Existing Xaero first-spawn gaps, the 1.21.1 low-view-distance corner seam, region-boundary shading seams and shader/LOD-depth limits remain.
- After `--forceUpgrade` or `--eraseCache`, LODs can be dark until the chunks are re-saved. This is documented in troubleshooting.

## Publication handoff

- **LSS:** 16 jars. Fabric and Paper on all six lines, plus NeoForge on 26.3, 26.2, 26.1 and 1.21.1 (`LINE_SHIP_NEOFORGE`). The LSS NeoForge jars for 1.21.10 and 1.21.11 are built and checked but not published.
- **VSS:** all 18 jars (three loaders on six lines) are built and checked. VSS publication (local, `84zcagOb`) is a separate decision.
- **Order of operations, after authorization:** merge PRs #343–#348 with **merge commits only**. A squash or rebase would orphan the pinned SHAs.
- **Tags:**
  - Annotated tags with `--cleanup=verbatim`, put on the merge commits.
  - `v0.18.0` for 26.3, which is the only line with the Latest badge.
  - `v0.18.0+mc26.2`, `+mc26.1`, `+mc1.21.11`, `+mc1.21.10` and `+mc1.21.1` for the others.
  - Notes come from `docs/planning/v0.18.0-release-notes/<main|mc26.2|mc26.1|mc1.21.11|mc1.21.10|mc1.21.1>.md`.
  - Push tags one at a time. `release.yml` refuses a tag whose suffix disagrees with the branch's `line.env`.
- **After publishing:** verify six GitHub releases and 16 LSS Modrinth versions. Recover any partial publish from the attached artifacts and never rerun the release workflow.
