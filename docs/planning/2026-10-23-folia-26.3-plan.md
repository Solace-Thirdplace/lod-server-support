# Folia on the 26.3 line (v0.19.1)

Status: PLANNED v2 (2026-10-23), plan review folded (§8). User request: "come up with a plan for releasing [Folia support
on 26.3] and execute it" — the request is the approval. Plan review: §8.

## 1. Why

PaperMC published Folia for 26.3 after the 0.19.0 release:

| Build | Channel | Published (UTC) |
| --- | --- | --- |
| 3 | ALPHA | 2026-10-14 |
| 4 | ALPHA | 2026-10-20 |
| 5 | ALPHA | 2026-10-20 |

Main (26.3) still ships `folia-supported: false` because Folia had no 26.3 build when the line was
cut, so Folia refuses to load the LSS 26.3 Paper jar. The same code already runs on Folia 26.2,
26.1.2 and 1.21.11 (experimental). The 26.2 precedent (2026-08-01): Folia published 26.2-1, we
re-declared the flag on that line and ran the Folia soaks.

## 2. Change

One line fact, single-sourced since port-isolation round 2 (R2-5):

| File | Change |
| --- | --- |
| `.github/line.env` | `LINE_PAPER_LOADERS=paper purpur folia` |
| `config/compatibility/line.json` | `paper_loaders` gains `folia` (catalog line facts) |

Everything else derives from those:
- `paper/build.gradle` expands `folia-supported: true` into `plugin.yml`;
- `release_check.py` (`FOLIA_SUPPORTED`) requires the flag in the release and VSS jars;
- `release.yml` publishes the Paper jar to Modrinth with the `folia` loader;
- `catalog.py` renders the 26.3 row with Folia `experimental` (catalog table and the README
  matrix between its markers).

One line-flavor pin flips by hand: `ReleaseWorkflowContractTest`'s mainline block asserted that
`LINE_PAPER_LOADERS` must NOT contain `folia` ("no Folia 26.3 exists"). It now asserts the
opposite, worded like the 26.2 line's block. `PluginYmlContractTest.foliaSupportedDerivesFromLineEnv`
already follows `line.env`, so it needs no edit.

Docs (line-local except the rendered catalog):
- `CLAUDE.md`: line 3 no longer says Folia has no 26.3 build. It says Folia 26.3 is ALPHA upstream
  and the line ships Paper/Purpur/Folia (Folia experimental).
- `README.md`: the 26.3 row of the support table shows Folia experimental.
- `docs/compatibility.md`: re-rendered by `catalog.py render`.
- Stale comments that say 26.3 has no Folia build, wherever a grep finds them.

No Java change, no settings, no wire or protocol change, no client-visible change.

## 3. What stays

- **Folia stays EXPERIMENTAL** (settled; RULES.md §b). Every soak is single-player. The exit
  criterion is concurrent multi-region ingress, which this plan does not test.
- Folia 26.3 itself is an ALPHA upstream. The release note says so.
- No other line changes behaviour. The five support lines only take the six-line re-pin.

## 5. Release

- **Version 0.19.1**, a patch on the 26.3 line only: tag `v0.19.1` (Latest). Fabric, NeoForge and
  Sponge 26.3 republish unchanged code under the new version; that is how `release.yml` works.
- **The five support lines** get the re-pin commit through a PR each (no version bump, no tag).
- **Every line's README and `docs/compatibility.md` change** in its re-pin commit: `catalog.py
  render` writes the README matrix from the pinned rows, so the 26.3 row turns "experimental" on
  all six lines. Never hand-edit the matrix.
- **Notes** (`docs/planning/v0.19.1-release-notes/main.md`), 0.19.0 shape. RULES.md: Folia notes
  omit the "experimental" label (user decision 2026-08-28), confirm the wording at tag time:

  ```markdown
  ### Support

  - **Folia 26.3** — The Paper plugin now also runs on Folia 26.3. Folia's own 26.3 builds are still alpha.
  - **Platforms** — Fabric, Paper/Purpur/Folia, NeoForge and Sponge (experimental) for Minecraft 26.3.
  ```
- **Records:** `docs/planning/2026-10-23-v0.19.1-release-preparation.md` and its manifest under
  `docs/implementation/`.
- **Tooling** (`~/.local/state/lss-release-prep-v0.19.1/`, `~/.local/state/lss-publish-v0.19.1/`):
  - `gate.sh`: version 0.19.1, 26.3 only.
  - `verify-lss.py`: 0.19.1, plus a new check that the Modrinth Paper version's loaders equal
    `LINE_PAPER_LOADERS` (the one new publish fact).
  - `publish-vss.py`: 26.3 only (4 rows); the Paper row's loaders come from the new `line.env`
    and must contain `folia` (copying the 0.19.0 VSS receipt would drop it).
  - `recover-modrinth.py`: 0.19.1; Paper display name derived from `LINE_PAPER_LOADERS` like
    release.yml.
  - `tag-chain.sh 0.19.1 26.3` pushes only `v0.19.1`.
- **VSS:** publish the four 26.3 versions only (Fabric, Paper with `folia`, NeoForge, Sponge).
- **Modrinth readme draft:** its 26.3 Folia cell flips to supported (backup `.bak-0.19.1`).
- **Modrinth test server and Prism rigs:** no deploy or refresh. Fabric code is unchanged; the
  next release with client or Fabric changes does it. (Saves the user a panel Start.)
- **GitHub:** no issue to answer (user-requested item).
